# Machine-language activity diagrams

The combined ca65 reconstructions contain 93 semantic code labels. Each label has a Mermaid activity diagram:

- [BP.ML activity diagrams](BP-ML-Activity-Diagrams.md): 50 public vectors, initialization phases, inference helpers, backpropagation phases, pattern parsers, and persistence routines.
- [CL.ML activity diagrams](CL-ML-Activity-Diagrams.md): 43 public vectors, compatibility stubs, initialization phases, classification helpers, competitive-learning phases, pattern parsers, and persistence routines.
- [BP.ML and CL.ML data structures](../ML-DATA-STRUCTURES.md): exact BASIC model layouts, fixed RAM workspace maps, serialized file formats, and embedded read-only tables.

## Source hierarchy

Public entry-point behavior comes from the BASIC demonstrations:

- [XOR.bas](../../combined/basic/XOR.bas) and [ENCODE.bas](../../combined/basic/ENCODE.bas) call the backpropagation initialization, pair-definition, learning, and recognition vectors.
- [DIPOLE.bas](../../combined/basic/DIPOLE.bas) calls the competitive-learning initialization, pattern-definition, and learning vectors. Its REM interface block documents recognition and save/load.
- Entry vectors absent from executable BASIC call sites are labeled as such in their diagrams.

Internal control flow comes from [BP.ML.s](../../combined/asm/BP.ML.s) and [CL.ML.s](../../combined/asm/CL.ML.s), with the reconstructed comments and BASIC ROM call targets providing operation names.

## Coverage rule

A function is every named semantic code label before each source file's `DimExpressions` data table. This includes public jump-table vectors, compatibility stubs, callable helpers, and named fall-through phases. The inventory excludes:

- ROM, KERNAL, and workspace equates.
- `PayloadStart` and `PayloadEnd`.
- Autogenerated address labels such as `LCA6F`.
- Embedded DIM strings, variable names, and floating-point constants.

The diagrams intentionally group individual 6502 instructions into operations and decisions. They document the reconstructed control flow; they do not replace emulator or physical-C64 runtime validation.
